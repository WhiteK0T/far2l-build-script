# far-build

Автоматизированный bash-скрипт для сборки и установки `far2l` из исходного кода на Debian/Ubuntu-подобных системах.

## 🚀 Возможности
- ✅ Автоматическое определение версии ОС и дистрибутива
- 📦 Выбор пакета wxWidgets (3.2 или 3.0) по фактическому наличию в репозиториях — работает и на Mint, Pop!_OS и других производных
- 🖼️ Выбор графического интерфейса: wxWidgets, SDL или оба сразу (`--gui`)
- 🗜️ Установка 7-Zip для работы с архивами (`7zip` или `p7zip-full` в старых системах)
- ⚡ Параллельная сборка с использованием всех ядер CPU
- 🛡️ Безопасное выполнение (`set -euo pipefail`, проверка прав root)
- 🧹 Автоматическая очистка временных файлов — в том числе при ошибке
- 🎨 Цветное логирование для удобного отслеживания прогресса

## 🖥️ Поддерживаемые системы
| Дистрибутив | Версии |
|-------------|--------|
| Ubuntu      | 22.04 LTS, 24.04 LTS |
| Debian      | 12 (Bookworm), 13 (Trixie) |

> 💡 На других apt-системах скрипт тоже работает, если в репозиториях есть `libwxgtk3.2-dev` или `libwxgtk3.0-gtk3-dev`. На системах без `apt-get` он сразу завершается с ошибкой.

## 📋 Требования
- Права `root` или `sudo`
- Стабильное интернет-соединение
- ~500 МБ свободного места на `/tmp` и в каталоге установки (по умолчанию `/usr/local`)
- `bash 4.0+` (стандартно в современных дистрибутивах)

## 🛠️ Установка и запуск
```bash
# 1. Скачать скрипт
curl -fsSL https://raw.githubusercontent.com/WhiteK0T/far2l-build-script/refs/heads/main/far-build.sh -o far-build.sh

# 2. Просмотреть скрипт перед запуском от root
less far-build.sh

# 3. Сделать исполняемым
chmod +x far-build.sh

# 4. Запустить от имени root
sudo ./far-build.sh
```

### Выбор графического интерфейса
| Команда | Что собирается | Запуск |
|---------|----------------|--------|
| `sudo ./far-build.sh` | wxWidgets (по умолчанию) | `far2l` |
| `sudo ./far-build.sh --gui=sdl` | только SDL, без wxWidgets (экспериментальный) | `far2l --SDL` |
| `sudo ./far-build.sh --gui=both` | wxWidgets и SDL | `far2l` или `far2l --SDL` |

Для SDL дополнительно ставятся `libsdl2-dev`, `libfreetype-dev`, `libharfbuzz-dev` и `libfontconfig-dev`. Справка: `./far-build.sh --help`.

## 🐧 Gentoo
Скрипт рассчитан на `apt`. Для Gentoo в каталоге [`gentoo/`](gentoo/) лежит оверлей с ebuild `app-misc/far2l` (релиз и `9999` из git) и USE-флагами `wxwidgets`, `sdl`, `X`, `ssh`, `samba` и другими. Как подключить — в [gentoo/README.md](gentoo/README.md). О новых версиях far2l сообщает GitHub Actions: workflow сам открывает PR с обновлённым ebuild.

## ⚙️ Как это работает
1. Разбирает аргументы (`--gui`, `--help`), проверяет права `root` и включает строгий режим выполнения
2. Проверяет наличие `apt-get` и читает `/etc/os-release` (для лога)
3. Обновляет `apt` и собирает список пакетов: для WX выбирает доступный `wxWidgets` (сначала 3.2, затем 3.0), для SDL добавляет библиотеки SDL, а также 7-Zip
4. Устанавливает пакеты, клонирует репозиторий `--depth 1` во временный каталог `mktemp -d`
5. Конфигурирует проект через `cmake` (`-DUSEWX` / `-DUSESDL` по выбранному `--gui`), собирает с `-j$(nproc)`
6. Устанавливает far2l в `/usr/local` и сохраняет список установленных файлов в `/usr/local/share/far2l-build/install_manifest.txt`; временные файлы удаляются через `trap` при любом завершении

## 🎛️ Кастомизация
| Параметр | Как изменить |
|----------|--------------|
| Путь установки | Измените переменную `INSTALL_PREFIX` в скрипте (например, `/opt/far2l`) |
| Отладочная сборка | Замените `Release` на `Debug` |
| Сохранить исходники | Уберите строку `trap cleanup EXIT` |
| Включить verbose-лог | Добавьте `set -x` после `set -euo pipefail` |

## 🗑️ Удаление
Скрипт сохраняет список установленных файлов, по нему far2l можно удалить:
```bash
sudo xargs -d '\n' rm -fv < /usr/local/share/far2l-build/install_manifest.txt
sudo rm -rf /usr/local/share/far2l-build
```
После этого могут остаться пустые каталоги `far2l` в `/usr/local/lib` и `/usr/local/share` — их можно удалить вручную.

> Если вы меняли `INSTALL_PREFIX`, замените `/usr/local` на свой путь.

## 🐛 Решение проблем
- **`apt: unable to locate package`** → Проверьте версию ОС. Скрипт сам выбирает доступный пакет wxWidgets (`libwxgtk3.2-dev` или `libwxgtk3.0-gtk3-dev`). Если ошибка сохраняется, обновите репозитории вручную: `sudo apt update`
- **`cmake: not found`** → Скрипт устанавливает `cmake` сам. Если ошибка всё же появилась, проверьте, что шаг установки зависимостей прошёл без ошибок, или поставьте пакет вручную: `sudo apt install cmake` (в `build-essential` его нет)
- **Сборка прервалась** → Проверьте свободное место на диске и доступ к интернету. Временные файлы удаляются автоматически, поэтому скрипт можно просто запустить заново.

## 🏷️ Выпуск новой версии
Проект следует [Semantic Versioning](https://semver.org/lang/ru/): версия `MAJOR.MINOR.PATCH`.

| Что изменилось | Команда | Пример |
|----------------|---------|--------|
| Только исправления, совместимые с прежней версией | `./tools/release.sh patch` | 1.2.0 → 1.2.1 |
| Новые возможности, прежнее поведение сохранено | `./tools/release.sh minor` | 1.2.0 → 1.3.0 |
| Несовместимые изменения (убран ключ, сменено поведение по умолчанию, удалён USE-флаг) | `./tools/release.sh major` | 1.2.0 → 2.0.0 |

Изменения копятся в разделе `[Unreleased]` файла `Changelog.md`. Скрипт переносит их в раздел новой версии, создаёт коммит `release: X.Y.Z` и тег `vX.Y.Z`; публикация — `git push origin HEAD --tags`. Посмотреть результат без изменений: `--dry-run`. Опубликованную версию не меняют — исправления выходят новой версией.
